## Використання

```bash
sipl check examples/gcd.sipl
sipl parse examples/gcd.sipl -f text|json|dot [-o файл]
sipl ast examples/gcd.sipl
sipl term examples/log.sipl --style ascii --explain --pretty --json
sipl eval examples/log.sipl -s "X=3,Y=7" --trace --verbose --limit 100000 --json
sipl prove examples/mult.sipl --spec examples/spec_mult.json
sipl prove examples/mult.sipl --pre "y >= 0" --post "p = x * y" \
     --inv "p + x * k = x * y and k >= 0" --variant k --backend auto|z3|bounded
```

Коди завершення: `0` — успіх; `1` — помилка (синтаксис/специфікація) або спростовано; `3` — значення не визначене;
`4` — не доведено. З `--json` вивід машинночитний.

Приклад: `sipl eval examples/gcd.sipl -s "M=8,N=16"` → `[M ↦ 8, N ↦ 8]`.
Терм програми `log.sipl`: `AS^K(0̄) · WH(S¹(neg, S²(gr, X⇒, Y⇒)), AS^Y(S²(div, Y⇒, X⇒)) · AS^K(S²(add, K⇒, 1̄)))`.

## Мова

Граматика — БНФ практикуму 1 (єдине розширення — `div`), закладена в `src/sipl/parser.py`.

## Обмеження (чесно)

- У SIPL немає `<`, `<=`: умови лише `=`, `>`, `∨`, `¬`. Мова тверджень (`>=`, `and`, `=>` тощо) — наше додаткове розширення.
- `div` — розширення курсу; в обчисленні це цілочисельне ділення з округленням вниз, у доведеннях визначеність вимагає дільника > 0.
- Парсер повідомляє про першу синтаксичну помилку (без відновлення).
- Z3 необов'язковий. Без нього працює обмежений перебір: він може знайти контрприклад, але **не доводить**.
- Степенів у твердженнях немає. У доведеннях усі змінні вважаються визначеними.
- Невдала умова верифікації — контрприклад до **анотації** (інваріанта), а не до програми. Програму спростовує лише реальний запуск (динамічна перевірка).
- Обчислення має ліміт ітерацій та ліміт розміру чисел (4096 біт): тоді результат «не визначено».
